# Что нужно от заказчика для старта

Этот файл — единственный список данных, без которых система не начнёт работу.
Каждый пункт содержит: зачем он нужен, как его получить, куда положить и как
проверить, что он на месте. Ничего не нужно присылать в чат: значения
вписываются в `.env` прямо на вашем сервере.

Проверка готовности — одна команда:

```bash
python scripts/preflight.py            # конфигурация, без сети
python scripts/preflight.py --network  # плюс Redis, PostgreSQL и целевые сайты
```

Коды возврата: `0` — можно запускать, `1` — не хватает данных, `2` — проверить
нечем (нет пакетов или файла). Отчёт называет каждый незаполненный пункт по
имени — искать по документации не нужно.

## 1. VPS с SSH и Docker

**Зачем.** Система живёт на вашем сервере: код, сессии, доказательства и логи не
покидают его.

**Что нужно.**

- Ubuntu 22.04 LTS или новее, 2+ vCPU, 4 ГБ RAM, 20 ГБ диска.
- Docker и Docker Compose (`docker --version`, `docker compose version`).
- SSH-доступ для нас на время настройки — или вы выполняете команды сами, мы
  даём точные строки и проверяем результат по логам.
- Открытые порты: `22` (SSH) и `9090` (метрики, только для вас).

**Проверка.**

```bash
ssh <user>@<host> 'docker --version && docker compose version && free -h && df -h /'
```

**Чего не нужно.** Root-пароль в чат. Достаточно отдельного пользователя с
`sudo` и ключа, который вы отзовёте после сдачи.

---

## 2. Токен Telegram-бота

**Зачем.** Telegram — пульт управления: постановка задач, подтверждение
необратимых действий, алерты.

**Как получить.** В Telegram открыть [@BotFather](https://t.me/BotFather) →
`/newbot` → имя → username, заканчивающийся на `bot`. В ответ приходит строка
вида `123456789:AAH...`.

**Куда.** `.env`:

```dotenv
BOT_TOKEN=123456789:AAH...
```

**Проверка.** `preflight.py` проверяет не только наличие, но и формат
(`цифры:строка`), поэтому обрезанный при копировании токен виден сразу.

```bash
python scripts/preflight.py | grep BOT_TOKEN
```

**Важно.** Токен = полный доступ к боту. Если он попал в переписку — перевыпустите
его у @BotFather (`/revoke`) и впишите новый.

---

## 3. Числовой Telegram ID администратора

**Зачем.** Бот слушает только один ID. Остальные не могут ни ставить задачи, ни
подтверждать действия — даже если найдут бота.

**Как получить.** Написать [@userinfobot](https://t.me/userinfobot), он ответит
числом (`Id: 123456789`). Это не `@username` и не номер телефона.

**Куда.** `.env`:

```dotenv
BOT_ADMIN_ID=123456789
```

**Проверка.** `preflight.py` отвергает `0`, пустое значение и текст вместо числа.

---

## 4. Ключ LLM-провайдера

**Зачем.** Именно модель выбирает следующее действие в браузере и меняет план,
когда вы уточняете задачу обычным текстом. Без ключа система запускается, но
решения не принимает: в лог уходит предупреждение, в чат — честный отказ.

**Что нужно — один из вариантов.**

| Провайдер | `LLM_BASE_URL` | `LLM_MODEL` | Где взять ключ |
|-----------|----------------|-------------|----------------|
| OpenAI | `https://api.openai.com/v1` | `gpt-4o` | platform.openai.com → API keys |
| OpenRouter | `https://openrouter.ai/api/v1` | `anthropic/claude-3.5-sonnet` | openrouter.ai → Keys |
| Свой сервер (Ollama, vLLM) | `http://localhost:11434/v1` | `llama3.1` | ключ не нужен, поставьте любой непустой¹ |

¹ Для локальной модели `LLM_API_KEY` всё равно должен быть непустым — это
признак «автономный режим включён». Подойдёт значение `local`.

**Куда.** `.env`:

```dotenv
LLM_API_KEY=sk-...
LLM_BASE_URL=https://api.openai.com/v1
LLM_MODEL=gpt-4o
LLM_TEMPERATURE=0.3
LLM_MAX_TOKENS=2000
```

**Проверка.**

```bash
python scripts/preflight.py | grep LLM_
```

`LLM_BASE_URL` и `LLM_MODEL` имеют рабочие значения по умолчанию, поэтому их
отсутствие — не ошибка; отчёт так и пишет: «по умолчанию».

**Расходы.** Одна задача — обычно 3–10 обращений к модели. Ключ принадлежит вам,
счёт выставляется вам, лимит можно поставить на стороне провайдера.

## 5. Пароли Redis и PostgreSQL

**Кто делает.** Мы: генерируем случайные значения на сервере и вписываем в
`.env`. От вас нужно только согласие на генерацию — придумывать пароли вручную
не надо.

```bash
openssl rand -base64 24   # для REDIS_PASSWORD
openssl rand -base64 24   # для DB_PASSWORD
```

**Куда.** `.env`:

```dotenv
REDIS_PASSWORD=<сгенерировано>
DB_PASSWORD=<сгенерировано>
```

**Проверка.**

```bash
python scripts/preflight.py --network
```

Проверка действительно подключается к Redis (`PING`) и PostgreSQL (`SELECT 1`), а
не смотрит на наличие переменной. Если контейнеры ещё не подняты — пункт будет
красным, и это ожидаемо до шага запуска инфраструктуры.

## 6. Вход по QR в кабинеты

**Зачем.** Пароли от Ozon, Авито, WB и почты нам не нужны и не должны
передаваться. Вход выполняется один раз вручную: вы сканируете QR телефоном в
окне браузера на своём VPS и проходите капчу, если она появится. Дальше агент
работает в этой же сессии — она сохраняется в профиле Chromium.

**Что нужно.**

- Телефон с приложением маркетплейса (или почты).
- 5–10 минут на каждый аккаунт.
- Один отдельный профиль на каждый аккаунт: `browser-profile-ozon`,
  `browser-profile-avito`, `browser-profile-wb`.

**Как.** Для каждого кабинета — своя команда. Скрипт открывает страницу входа,
каждые 15 секунд сохраняет скриншот и ждёт признак входа.

```bash
# Ozon
python scripts/qr_login.py --url https://www.ozon.ru \
    --success-selector "<селектор личного кабинета>" --show

# Авито
python scripts/qr_login.py --url https://www.avito.ru \
    --success-selector "<селектор профиля>" --show

# Wildberries
python scripts/qr_login.py --url https://www.wildberries.ru \
    --success-selector "<селектор профиля>" --show
```

**Про селектор.** Селекторы личного кабинета у площадок меняются, поэтому в
команде стоит плейсхолдер: мы определяем актуальный селектор на вашем сервере в
день входа и подставляем в команду. Это единственное значение, которое нельзя
заготовить заранее.

**Коды возврата — они же ответ на вопрос «вошли или нет».**

| Код | Значение |
|-----|----------|
| `0` | Вход подтверждён, профиль сохранён |
| `1` | За отведённое время вход не подтверждён |
| `2` | Критерий проверки не задан — подтвердить нечем |

Код `2` существует намеренно: скрипт не имеет права сказать «вошли», если
проверять нечем. Скриншоты лежат в `evidence/qr-login/` — их видно в Telegram и
можно посмотреть глазами.

**Профиль на диске.** Права `0700`, вне git. Если профиль нужно копировать в
бэкап или переносить на другую машину, включите шифрование:

```dotenv
BROWSER_PROFILE_ENCRYPTION=true
```

Ключ создаётся сам в `~/.secrets/browser-profile.key` (0600). Профиль
шифруется при остановке и расшифровывается при запуске; маркер
`.profile-encrypted` не даёт принять наполовину зашифрованный профиль за целый.
По умолчанию выключено: для работы на одном сервере достаточно прав `0700`.

**Чего не нужно.** Пароли, коды из SMS и seed-фразы 2FA. Если площадка просит
их — вы вводите их сами в окне браузера, мы их не видим и не сохраняем.

## 7. Прокси для браузера (если нужен)

**Зачем.** Некоторые маркетплейсы ограничивают доступ с IP дата-центров. Признак:
`preflight.py --network` показывает `HTTP 403` для сайта, а в браузере страница
не открывается.

**Что нужно.** Прокси в формате `http://user:pass@host:port` или
`socks5://host:port`. Если сайты открываются напрямую — пункт пропускается.

**Куда.** `.env`:

```dotenv
BROWSER_PROXY=http://user:pass@host:port
```

**Проверка.**

```bash
python scripts/preflight.py --network
```

Проверка идёт к `ozon.ru`, `avito.ru`, `wildberries.ru` и печатает HTTP-код для
каждого. Код `5xx` и сетевые ошибки — красный пункт; `403` виден как код ответа и
означает, что нужен прокси.

## 8. Репозиторий для кода

**Зачем.** Код должен лежать в вашем аккаунте, а не только на сервере: это
страховка от потери, возможность передать проект другому специалисту и история
изменений.

**Что нужно.** Пустой приватный репозиторий GitHub/GitLab в вашем аккаунте плюс
права на push (deploy key или приглашение).

**Куда.** `git remote set-url origin <ваш репозиторий>`.

**Проверка.**

```bash
git push -u origin main && git log --oneline -3
```

**Важно.** `.env`, профили браузера, доказательства и ключи в репозиторий не
попадают — это закрыто в `.gitignore` и проверяется в CI.

## 9. Контакт для алертов

**Зачем.** При сбое вы узнаёте сразу, а не через неделю: бот пишет в Telegram в
момент инцидента.

**Что нужно.** Тот же числовой ID, что в п. 3, или отдельный чат для алертов.

**Проверка.** Тестовый алерт в первый день настройки — вы видите сообщение и
подтверждаете, что оно дошло.

## 10. Критерии приёмки

Фиксируются до старта, чтобы «готово» не спорило с ожиданиями. Предлагаемый
список — по одному наблюдаемому пункту на каждое обещание:

| № | Проверка | Как наблюдается |
|---|----------|-----------------|
| 1 | Бот отвечает только вам | сообщение с чужого аккаунта остаётся без ответа |
| 2 | Задача ставится текстом | ответ с номером задачи и статусом |
| 3 | Модель выбирает действие | в логе видно «мысль → действие → результат» |
| 4 | План меняется после уточнения | после обычного сообщения в логе шаг `clarification`, следующий шаг другой |
| 5 | Вход по QR переживает перезапуск | после рестарта задача выполняется без повторного входа |
| 6 | Необратимое действие ждёт подтверждения | бот присылает вопрос с кнопками и не действует до ответа |
| 7 | Результат подтверждён фактами | скриншот, видео и trace в `evidence/` |
| 8 | Сбой виден | остановленный Redis даёт алерт, а не тишину |

Пункт считается принятым, когда проверка выполнена на живой системе и результат
показан вам. «CI зелёный» приёмкой не является.

## Чего мы не просим

- Пароли от кабинетов, коды из SMS, seed-фразы 2FA.
- Номера банковских карт и CVV — оплата выполняется вами, агент только доводит
  заказ до шага оплаты и ждёт подтверждения.
- Root-пароль сервера в переписке.
- Персональные данные третьих лиц — до отдельного согласования по 152-ФЗ.

## Порядок старта

1. Заказчик присылает: доступ к VPS, токен бота, свой Telegram ID, ключ LLM,
   адрес репозитория.
2. Мы генерируем пароли Redis/PostgreSQL и вписываем всё в `.env` на сервере.
3. `python scripts/preflight.py` — зелёный отчёт по конфигурации.
4. Поднимаем инфраструктуру, `preflight.py --network` — зелёный отчёт по сети.
5. Заказчик входит по QR в каждый кабинет (`scripts/qr_login.py`, код `0`).
6. Прогоняем первые задачи и фиксируем приёмку по списку из §10.

Каждый шаг проверяется до перехода к следующему: молчаливый пропуск шага — это
не «сделано», а неизвестность.
