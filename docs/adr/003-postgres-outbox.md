# ADR-003: Выбор PostgreSQL для транзакционного outbox

## Статус
Принято

## Контекст
Для надёжной доставки событий требуется транзакционный outbox, который гарантирует:
- Атомарную запись события вместе с бизнес-изменением
- Идемпотентную доставку
- Сохранение порядка событий

## Рассмотренные варианты

### Вариант A: Redis Streams
**Плюсы:**
- Уже используется в проекте
- Быстрая работа

**Минусы:**
- Нет транзакционной гарантии с бизнес-базой данных
- События могут потеряться при сбое Redis

### Вариант B: PostgreSQL (выбран)
**Плюсы:**
- Транзакционная надёжность (запись события вместе с бизнес-изменением в одной транзакции)
- Надёжное хранение
- Поддержка индексов для эффективного извлечения необработанных событий

**Минусы:**
- Требуется отдельная таблица
- Более высокая задержка по сравнению с Redis

## Решение
Используем PostgreSQL для транзакционного outbox с таблицей `outbox` и отдельным диспетчером для публикации событий.

## Последствия
- Требуется развёртывание PostgreSQL
- Outbox диспетчер запускается отдельно от основного приложения
- События гарантированно не теряются при сбое приложения

## Связанные решения
- ADR-002: Выбор Redis для очереди задач (Redis для выполнения задач, PostgreSQL для надёжности событий)
