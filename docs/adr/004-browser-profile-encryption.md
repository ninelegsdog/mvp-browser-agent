# ADR-004: Шифрование профиля браузера

## Статус
Принято

## Контекст
Профиль браузера Chromium содержит конфиденциальные данные:
- Куки и сессии аккаунтов (Ozon, Avito, WB, почта)
- Локальное хранилище
- Кэш и другие данные

Профиль хранится на диске и может быть доступен злоумышленнику при компрометации сервера.

## Рассмотренные варианты

### Вариант A: Нет шифрования
**Плюсы:**
- Простота
- Нет дополнительной зависимости

**Минусы:**
- Профиль доступен любому, кто имеет доступ к диску
- Сессии могут быть украдены

### Вариант B: Шифрование всего диска (LUKS)
**Плюсы:**
- Полное шифрование всех данных на диске

**Минусы:**
- Требует настройки на уровне ОС
- Сложность управления ключами
- Не гибко для отдельных профилей

### Вариант C: Шифрование каталога профиля через Fernet (выбран)
**Плюсы:**
- Простая реализация
- Ключ хранится отдельно в ~/.secrets/
- Автоматическое шифрование/расшифровка при запуске/остановке
- Не требует изменений в ОС

**Минусы:**
- Требуется управление ключом шифрования
- Профиль недоступен без ключа

## Решение
Используем симметричное шифрование Fernet (AES-128 в режиме CBC с HMAC-SHA256) для профиля браузера. Ключ хранится в ~/.secrets/browser-profile.key с правами 0o600.

Профиль расшифровывается перед запуском браузера и шифруется после остановки.

## Последствия
- При потере ключа профиль недоступен (требуется повторный вход через QR)
- Небольшая задержка при запуске/остановке из-за шифрования/расшифровки
